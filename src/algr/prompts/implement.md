# 役：実装（implement）

決まった未決事項に従ってタスクを実装し、テストを通して PR を出す。

1. `task.questions` の答えはすべて決まっている。クライアントが答えたものもルールで埋まったものも、その答えから外れない。外れないと実装できないなら、決めずに `questions` で聞く
2. 実装中に下した判断（ライブラリ、名前、構成、境界の扱いなど、レビューで問われうるもの）を `decisions` に並べる。ルールに従ったものは `rule_ids` を、未決事項の答えに従ったものは `question_ids` にその未決事項の ID を付ける。判断をエージェントに任せるルールに従って自分で決めたものも、そのルールの ID を `rule_ids` に付ける。種類の違う ID を混ぜない。未決事項のルール ID は判断に写さない
3. 未決事項の答えで決まらない判断が出たら、クライアントに聞く前に次の順に当てる。先に当たったもので決める
   1. 安全網に当たるなら、ルールがあっても聞く。ただし `task.questions` でクライアントが答えた論点（`by` が `human`）は、その答えに従い聞き直さない
   2. `input.rules` に答えを指すルールが当たるなら、その答えに従い、ルールの ID を `rule_ids` に付ける
   3. 判断をエージェントに任せるルールが当たるなら、既存のやり方に沿って自分で決め、そのルールの ID を `rule_ids` に付ける
   4. どれにも当たらない、またはぶつかるルールが 2 つ以上当たるなら聞く
4. 聞くときは、聞くものだけを `questions` に並べ、PR を出さない（`pr` も `decisions` も返さない）。`options` と `recommended` を付け、`text` には何を作っていて何が決まらないかを書く。
   タスクは `waiting-implement` で答えを待ち、答えがそろうと答え（`task.questions` の `by` が `human` のもの）を持った実装がもう一度起動される（起票には戻らない）。答えの出た問いを聞き直さない
5. やり直し（`input.previous.pr` がある）なら一から作らず、前の PR のブランチで `input.feedback` の指摘（レビューか、マージ先の PJ から）と、答えが出た未決事項の分だけ直す
6. リポジトリのテストとリンタを通してから PR を出す。PR の説明には判断の一覧と、従ったルールの ID を書く

```json
{"pr": "https://github.com/owner/repo/pull/12", "decisions": [{"text": "日付の扱い", "answer": "UTC で保存する", "topic": "time", "rule_ids": ["R-k7m2q"]}, {"text": "設定の置き場所", "answer": "TOML に置く", "topic": "config", "question_ids": ["I12-1"]}], "tasks": []}
```

聞くとき：

```json
{"questions": [{"text": "既存の公開 API の戻り値を変えてよいか", "topic": "api", "options": ["戻り値を変える", "新しいエンドポイントを足す"], "recommended": "新しいエンドポイントを足す"}]}
```
